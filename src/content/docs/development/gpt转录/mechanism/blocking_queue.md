# 阻塞队列（Blocking Queue）

## 概述

阻塞队列为文言程序提供生产者—消费者协作能力。队列为空或已满时，相关操作可以暂停当前执行请求，并在条件满足后恢复。

> 原文标题就叫「feature」，这里给它起个更贴切的名字。

## 外观

用「纸」的模型来表示（具体外观以最终实现为准）。

## 功能

对外提供这些操作：

| 函数 | 行为 |
| --- | --- |
| `put(blocked)` | **放入**。队列满了就**阻塞**等待 |
| `take(blocked)` | **取出**。队列空了就**阻塞**等待 |
| `offer?` | 非阻塞放入，放不进去**返回 false** |
| `poll?` | 非阻塞取出，队列空**返回 null** |
| `peek?` | 查看队头，空则**返回 null** |
| `clear` | 清空 |
| `size` | 返回当前大小 |

## 实现思路

### 内部结构

- 内部用 **array deque** 存数据。
- 另外维护**两个队列**：一个存「阻塞的生产者」，一个存「阻塞的消费者」。

### 与 Java 的关键差异

与 Java 阻塞队列不同，文言运行时不适合在解除阻塞后直接恢复原调用栈。因此采用以下策略：

> **被阻塞那一方的请求，由「解除阻塞的一方」来替它完成。**

也就是说：生产者做 `put`，消费者做 `take`，谁来解除阻塞，谁就把对方没做完的事给做了。

还有一个重要前提：**所有请求都发生在单线程里**。

### put 的步骤

1. 如果队列**满了** → 阻塞（生产者入队等待）。
2. 否则：
3. 把数据放进去。
4. 从消费者队列里取一个「正在阻塞的消费者」。
5. **替这个消费者执行 take**——但**不需要解除生产者的阻塞**，因为此时此刻生产者队列应该是空的。
6. 解除消费者的阻塞。

> 为什么「生产者队列应该是空的」？因为**任何会让 array deque 变小的操作，都会先从生产者队列里取**。所以只要 array deque 没满，就说明所有生产者都已经入队了，生产者队列必然为空。

### take 的步骤

1. 如果队列**空了** → 阻塞（消费者入队等待）。
2. 否则：
3. 取出数据。
4. 从生产者队列里取一个「正在阻塞的生产者」。
5. **替这个生产者执行 put**——同样不需要解除消费者的阻塞。
6. 解除生产者的阻塞。

### offer / poll

1. 如果满了 / 空了 → 直接返回 `false`（或 null）。
2. 否则 → 逻辑跟 `put` / `take` 一样。

### peek

队列空 → 返回 `null`；否则直接看队头。

### size

直接返回队列大小。

### clear

1. 队列空 → 什么都不做。
2. 否则：清空 array deque。
3. 循环：**从生产者队列里取生产者，直到队列填满**——也就是取 `min(capacity, 生产者数量)` 个。
4. 替这些生产者执行 `put`——**不需要解除阻塞**，因为此时消费者队列是空的（依据：队列当前非空这个事实）。

## 总结

该阻塞队列使用 `ArrayDeque` 保存数据，并分别维护等待中的生产者和消费者。解除阻塞的一方负责完成被暂停的操作，从而在不恢复原 Java 调用栈的情况下实现 `put`、`take`、`offer`、`poll`、`peek`、`clear` 和 `size`。

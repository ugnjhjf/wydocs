# 熔炉（Furnace）

## 目标

该方块提供统一的可编程烧炼能力，计划兼容熔炼、烟熏和高炉烧炼配方。

但光「能烧」还不够，它想玩点新花样：**玩家可以通过写函数来控制烧炼过程**，而且有两种思路完全不同的玩法。

### 两个「过程」函数 + 一个「查询」函数

方块对外暴露三个函数：

| 函数 | 作用 |
| --- | --- |
| `void burn()` | **加 1 点进度** |
| `void doubleBurn()` | **进度 × 2** |
| `int getProgress()` | **查询当前进度** |

### 两种操作模式

**玩法一：稳扎稳打型（一直 burn）**
每次调用 `burn()` 只加 1 点进度。这条路有两大好处：**不需要燃料**，而且**批量烧的时候速度会稍快一点**。

**高风险模式（`doubleBurn`）**
用 `doubleBurn()`，进度直接翻倍，**烧得飞快**，甚至能跟 Create 模组的鼓风机（blaster）掰手腕。但代价是——**有风险**。

### 超出目标进度的处理

如果进度**超过了**所需进度，物品会被**直接烧毁（消失）**。所以玩家必须**精确控制进度**，让它刚好等于所需值。

注意：这个「烧过头就烧毁」的惩罚**只作用于 ×2 玩法**。如果玩家一直用 `burn()` 加 1，那行为就跟原版完全一致，不会吃亏。

### 进度怎么算

- 进度由**物品的烧炼速度**决定。
- 批量增加时，进度会**按相同比例**增长，但会**扣掉一个随机数**（最多扣 50%，平均扣 25%）——一方面逼着玩家去「掌握」这个方块，另一方面也让整个过程更快。

## 设计

- **一个方块 + 两个容器**：上面放输入，下面放输出。
- **GUI**：基本复刻原版熔炉界面；**鼠标悬停在进度条上时**，用 tooltip 显示当前进度。

### 模块实现三个函数

```java
void burn();
void doubleBurn();
int getProgress();
```

## 实现细节

### 方块实体

- 持有**两个 itemstack 容器处理器**，外加一个 GUI 容器菜单。
- 当玩家放入物品 / 物品堆叠变化时：
  1. 检查配方，并设置 `neededProgress = time × count × reduce`；
  2. `reduce = 1 - random.double(0, min(count/64, 1) * 0.5)`；
  3. `neededProgress = max(neededProgress, 2)`；
  4. 把 `progress` 设为 1。

### 三个函数的实现

> 三个函数在动手前都会先**检查有没有配方**，没有就抛错误。

**1. `burn()`**
- 若 `progress >= neededProgress`：检查输出槽是否为空 / 能放入。能的话，**清空输入堆叠，把产出放进输出槽**（因为输入槽变了，进度会自动重新计算）；不行就什么都不做。
- 否则：`progress` 加 1。

**2. `doubleBurn()`**
- `progress == needed`：跟 `burn()` 的产出逻辑一样。
- `progress > needed`：**只清空输入槽**（物品烧毁了，没产出）。
- 否则：`progress` 翻倍（**要加一个整数溢出检查**）。

**3. `getProgress()`**
- 直接返回 `progress`。

## 总结

可编程熔炉提供稳定递增和进度翻倍两种模式。前者风险较低，后者速度更快，但超过目标进度会销毁输入。`burn`、`doubleBurn` 和 `getProgress` 三个函数共同驱动烧炼流程。

# 手持运行器（Hand Runner）

## 定位

手持运行器是一种低技术层级、可即时使用的代码执行工具，面向不需要复杂逻辑的短任务。与方块运行器相比，它具有更严格的功能和执行时间限制，并通过较高的消耗成本避免取代固定式运行器。

为什么这么设计？因为它想承担「**POC（概念验证）**」的角色：用这个物品先把一些「让模组运行器更容易跑起来」的小特性验证出来，探索一下方向。

## 功能特性

- **新物品**：新增一个手持物品。
- **右键使用**：右键消耗一个物品，召唤一个实体去运行代码。使用要加冷却（CD），像末影之眼 / 雪球那样。
- **写代码**：代码可以在刻印台（writing block）里写好。
- **挂载模块**：在合成台里，可以把模块挂到运行器上——但**只实现了少数几个函数**。被挂载的模块在调用完它所属的那个函数之后，就会被消耗掉。
- **限时存在**：给它一个**时间（tick）上限**，超过就消失。因为这只是给简单逻辑用的，绝大部分情况下这个时间完全够用。并且用**实体着火**的视觉效果提示玩家「时间快到了」——这也呼应了「符烧了才能用」的设定。
- **新手友好**：提供一些示例，让玩家能快速上手。
- **能导入模块**：可以从方块导入模块，运行器有**只放符的容器**。

## 实现设计

### 合成台那块

给合成台设计一个接口，让它能**接受多个类并写入**（也就是可扩展地挂载不同的模块实现）。

### 物品右键

重写右键逻辑：冷却可以抄原来那套实现，然后召唤一个运行器实体，剩下的事交给实体处理。

### 实体生命周期

重写 `tick` 函数：每 tick 把生命值 `life(int)` 减 1，减到 0 就把自己删除。

### 示例怎么来

示例以「原本物品 + 写好的代码组件」的形式提供，可以通过**创造模式物品栏**获得，也可以作为**村民交易 / 箱子战利品**出现。

### 模块函数实现

- **import 函数**：先从运行器自己的容器里找，也通过**自身位置**搜索范围内的方块来找。
- **方块里已有的函数**：直接调用是安全的——这个函数会被当作「在方块的 tick 里被调用」来执行。
- **容器里的函数**：实体的信息可以在上下文里拿到，可以进一步实现。请求的封装（wrapper）应该实现「让函数**删除实体容器里的符**」这个行为，并且在下一次调用时**检查容器里还有没有符**。

### 容器模块（inv module）

设计思路：

- 新增一个**继承 `IWenyanDevice` 的接口**，叫 `IInvDev` 之类的。
- 创建一个**新的 Capability 类型**：从 itemstack 的 capability 里拿到「设备名」和「原始执行包」。
- **名字**放在模块的组件里（从 itemstack 访问）；**执行包**放在物品上——因为不同 itemstack 之间它大多是相同的。
- 函数实现要**避免跟方块模块重复太多代码**：可能需要把公共部分抽成静态函数，让方块和物品两个实现共用。

## 总结

手持运行器 = 一个「低配、便携、限时、可挂模块」的符运行器。它的定位是 POC + 新手友好：右键召唤实体跑代码，时间到了就消失（着火提示），能挂模块、能导入方块里的函数。实现上重点做了实体生命周期管理、右键冷却、以及把方块/物品两种模块的公共代码抽出来复用。
